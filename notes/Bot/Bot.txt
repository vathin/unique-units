План Бота
1. Стабилизировать слой правил
   Довести get_legal_action_descriptors(player) до полного доверия: проверить все типы действий руками в игре, особенно торговца и move_ability_warrior. Цель: бот всегда выбирает из легальных ходов, а не “почти легальных”.
2. Добавить простой BotController
   Сделать BotController, который на своём ходу ждёт 20-40 кадров и вызывает:
   Game.game_loop_controller.perform_random_action(bot_player_id).
   Это даст первый живой smoke-test: бот ходит сам, игра не зависает.
3. Включить режим player vs bot
   В Start_match/меню добавить флаг режима:
   - local_vs_local
   - local_vs_bot
   - позже bot_vs_bot для тестов.
     Для бота можно использовать Player2 = new Player(2, "bot").
==================
4. Сделать оценку хода
   Заменить random на scoring:
   - захват/сброс фигуры врага: высокий плюс
   - потеря своей фигуры: минус
   - приближение к зонам завоевания: плюс
   - призыв полезной фигуры: плюс
   - бессмысленный ход назад/циклы: минус
   - торговец: плюс за призыв сильной/нужной фигуры.
5. Добавить симуляцию
   Сейчас perform_action_descriptor меняет настоящее поле. Для нормального бота нужен “примерить ход”:
   - экспортировать состояние поля
   - применить action
   - оценить результат
   - восстановить состояние.
     Это можно сделать поверх текущего Game.game_loop_controller.export/import, но осторожно, чтобы не триггерить UI/анимации/сервер.
6. Разделить Action на logic/ui
   Сейчас многие Action ещё вызывают O_BoardDraw, меняют marks/statuses и создают анимации. Нужно постепенно вынести:
   - execute_logic() без UI
   - preview_ui()/draw() отдельно
   - execute() может вызывать оба для обычной игры.
     Для бота и симуляции нужен только logic.
7. Сделать глубину поиска
   После простой оценки добавить minimax на 1-2 полухода:
   - получить свои legal actions
   - симулировать
   - получить ответы врага
   - выбрать ход с лучшим худшим исходом.
     Начать с глубины 1, потом 2, потому что ветвление может быть большим.
8. Ограничить кандидатов
   Чтобы minimax не тормозил:
   - сначала оценивать все ходы грубо
   - брать топ 10-20
   - глубже просчитывать только их.
     Особенно важно для торговца и щитоносца, где действий может быть много.
9. Добавить уровни сложности
   - Easy: random из нормальных действий
   - Normal: scoring без поиска
   - Hard: scoring + minimax depth 1-2
   - Debug: bot_vs_bot с логами.
10. Отладочные логи
       Добавить show_debug_message:
    - чей ход
    - сколько legal actions
    - выбранный descriptor
    - score
    - причина выбора.
         Это сильно ускорит настройку поведения.
